## 平板横屏与桌面基础

- Android 平板在原生 Activity 创建 Flutter 页面前请求横屏，修复冷启动仍为竖屏、进入播放器后才变横屏的问题。
- 手机启动方向保持竖屏；Android 16+ 若系统忽略大屏方向锁定，页面仍会按实际窗口尺寸回退响应式布局。
- `900dp` 以上横向窗口使用左侧一级导航；`1200dp` 以上展开导航文字，布局判断不绑定 Android，后续 Windows 可复用。
- 首页、搜索、“我的”改为横屏工作台双栏；主要二级页面统一居中限宽。

## 播放器与设置

- 平板播放器默认使用扩大的左侧视频区和 300–360dp 右侧辅助区，简介、UP 信息、学习清单、笔记、分P与合集不再被自动全屏隐藏。
- 左侧播放器填满可用工作区，视频 Texture 再按“适应画面 / 填充画面 / 拉伸铺满”处理，修复外层相同比例导致三个选项看起来无效。
- 手机横屏仍可使用沉浸全屏；平板从播放器返回后继续维持横屏工作台。
- 平板“我的”左侧账号卡使用专用纵向布局，不再把手机横向卡片拉满整栏高度。
- 个性化设置按“播放与专注”和“应用与存储”分为两栏，窄窗口自动回到单栏。
- 平板横屏非全屏播放器支持左侧竖滑调亮度、右侧竖滑调音量；顶部同步展示专注计时、本地时间、网络类型和电量。
- 设置新增 Wi-Fi 与移动网络两套默认清晰度；当前档位不可用时只向更低档回退，不会自动升档增加流量消耗。

## 宽屏内容页面

- 观看记录、收藏夹、收藏夹内容、订阅、订阅合集详情、关注和时间点笔记按父级可用宽度切换双列，手机和窄窗口继续使用单列。
- 专注数据在平板使用“指标趋势 / 记录管理”左右独立滚动工作台，手机继续按原顺序单列展示。
- 时间点笔记详情在宽屏分为视频来源与截图、标题与正文两个独立滚动区；窄窗口仍按原顺序回流。
- 播放器中的笔记摘要和常规编辑信息栏显示来源 `P序号`，快速切换旧笔记时不会丢失分P上下文。
- UP 主页资料头在宽屏横向排列头像、资料和统计，投稿与专栏使用双列，合集使用 2–4 列响应式网格。

## 播放恢复与弹幕

- Media3 遇到容器解析损坏时，只清理当前分P对应缓存并以无缓存数据源重试，不影响其他视频缓存。
- 备用视频、音频线路使用完整交叉组合，避免只尝试相同序号而漏过可播放搭配。
- 弹幕使用六分钟分段、100ms 时间桶、重复合并、关键词与类型前置过滤，并缓存文字和描边布局以减少逐帧开销。
- 片段晚到、重新开启、恢复历史进度或跳转时，当前位置以前的旧弹幕不会在屏幕中间补画。
- 服务端滚动、顶部、底部和反向基础类型仍可分别筛选，但展示方向统一为从播放器右边缘进入并向左完整穿屏，不再固定在中央或从左侧出现。分段与时间桶思路参考 [PiliPlus](https://github.com/bggRGjQaUbCoE/PiliPlus) 的公开实现。
- 高密度内容通过全局发射调度连续进入：九秒轨迹与六十条容量对应 150ms 最小间隔，最多排队两秒；超量内容在画布外丢弃，避免最老 60 条占满左半屏并遮掉右侧新弹幕。

## QQ、浏览器与 B站链接

- 支持 `bilibili://video/{AV或BV}`，以及 `bilibili.com`、`www.bilibili.com`、`m.bilibili.com` 的标准视频网页。
- 支持数字 AV 转 BV、网页分P `p`、Scheme 分P `page`、`cid` 和视频时间点。
- App 完全关闭时读取一次冷启动链接；App 已运行时复用 `singleTask` Activity 接收新链接。
- 外部链接不能绕过首次使用协议；仅查询公开视频详情，不增加 Cookie、不绕过会员、课程、充电、地区或其他访问控制。
- Scheme 和 AV/BV 兼容策略参考 GPL-3.0 开源项目 [PiliPlus](https://github.com/bggRGjQaUbCoE/PiliPlus) 的公开源码。
