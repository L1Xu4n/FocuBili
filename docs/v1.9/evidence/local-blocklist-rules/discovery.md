# 本机黑名单：投稿与焦点订阅

以前黑名单仅过滤搜索。本次也过滤已加载的公开 UP 主投稿和焦点订阅预览／更新列表，不新增推荐视频或推荐接口。

| 界面 | 可以匹配的已知资料 | 不推断的资料 |
| --- | --- | --- |
| UP 主公开投稿 | BV、标题、该视频明确返回的作者 UID／昵称与标签。公开接口是按指定 UID 查询该 UP 主的投稿，行未提供作者时可使用该投稿页的 UP 主资料；行提供了不同作者则以该行资料为准。 | 若已知昵称与主页不一致而该行没有 UID，不替它套用主页 UID。接口没传标签时不匹配标签规则。 |
| 首页焦点订阅预览、订阅更新 | 本机更新记录中的 BV、标题，以及明确来自一个 UP 主投稿源时由源键确定的 UID。 | 合集组织者不等于作者；有冲突的多个 UP 来源不推断 UID；订阅名称不是视频作者昵称。本机更新记录未提供视频标签。 |

只投影显示，不修改来源列表、原始投稿总数和翻页数据，也不因规则另发逐条详情／标签请求。投稿一页全隐藏会说明原因，仍可继续翻页或管理规则。订阅首页在隐藏后再选三条预览，未读总数仍是原始记录；存在隐藏的未读时，手动按钮明确只将显示项标为已读。规则变化本身不会更改读状态或发出、取消通知。若首次读规则失败，列表先保留为空并明确给出重试，不把失败当成空黑名单；后续刷新失败时保留上次显示，但在恢复权威规则之前不做依赖可见性的已读或学习操作。

收藏、观看历史、学习清单、下载、笔记、订阅设置和历史导入、已明确打开的公开合集与播放队列保持不变。离线条目和课堂直达不增加过滤或标签请求。

## 实际控件验证

- [投稿首批全部命中时仍可翻页](discovery-posts.png)：合成第一页有两个命中，原始总数仍为 3；实际点下一页读到第三支，移除规则后恢复前两支且不重新请求。注入计数器验证没有视频详情／标签请求。
- [首页只预览可见的三条，原始未读仍为 5](discovery-home.png)；[更新列表提示隐藏量和显示项已读按钮](discovery-feed.png)。规则变动前后本机订阅快照逐字节相同；只有用户明确标记已读才写入，隐藏的两项继续未读。
- 生产公开投稿 JSON 解析验证了作者与标签的存在／缺失分支，只使用原有公开投稿请求。测试还覆盖多个来源冲突、合集同名、未知作者保留、不借用别人的 UID。
