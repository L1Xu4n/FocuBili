## #56 规则与实现

- 点击开始专注后立即计时，不要求视频正在播放或先绑定视频。首页和播放器共用唯一控制器、唯一活动会话及同一个倒计时。
- 视频暂停、缓冲、快进、完播、切换分 P、切换视频、返回首页或搜索都继续同一会话；这些操作不计为完成、不新增专注记录，也不改变专注勿扰状态。
- 视频来源字段只保存最近观看书签（BV/CID、标题、位置、画面），供之后回到最近观看位置，不参与计时条件；打开新视频无需绑定确认。
- 点击**专注暂停**后停止累计，沿用原有打断原因/提醒流程。播放视频或换 P 不会偷偷恢复。点击**继续**恢复原会话，不要求任何视频正在播放。
- 应用进入 `hidden` / `paused` / `detached` 时暂停并只记录一次后台打断；回前台后等待用户主动继续。暂时的 `inactive` 状态只保存，不作为后台打断。
- 计划时间到后仅归档一次，按完整计划时长完成；手动结束按实际累计时长归档。已存在会话时重复开始被拒绝。历史统计按会话 ID 去重，活动记录与历史快照重叠时不重复累计。
- “当前分 P”时长选项改为“参考当前 P”：只把剩余时长作为计划长度。分 P 完播不会提前结束专注。旧 `completeOnPartEnd` 字段仍可解析历史记录，新会话恒为 false；恢复旧活动任务时清除该模式，保留 ID、累计时长和书签。
- 每约 15 秒结算一个运行检查点并串行保存。进程异常关闭后从最后保存的累计值恢复为暂停，不把离线时间算入。跨本地午夜仍按实际运行片段拆分每日统计。

涉及模型、全局控制器、存储队列、统计计算、首页和播放器专注面板，以及播放器专注协调器。播放器退出流程只保存书签，不再因退出弹出绑定/打断确认。

## #61 规则与存储

学习清单顶部支持“全部学科”“未分组”和用户创建的一级学科分组。分组可新建、重命名、删除；每条任务可单项移动，多选也可批量移动。加入清单的分 P 面板可直接选择学科。上限为 30 个分组，名称为 1–30 个 Unicode 码点，去除首尾空白后不允许同名；原有 100 条任务容量不变。

删除分组会把组内任务放回“未分组”，不会删除任务、观看记录或笔记。移动/重命名/删除均不重建学习条目：`stableId = BV:CID`、已保存进度、状态、顺序、加入时间保留。播放器按 BV/CID 更新既有条目的机制不变，存储写入按同一偏好实例排队，避免移动分组和播放进度互相覆盖。

全局学习顺序和首页继续学习逻辑维持原顺序；学科筛选只改变可见范围。分组内拖拽使用该分组原有全局位置槽位，不重排其他分组；会重新规范排序号，因此旧任务排序号重复时也能正确移动。搜索可匹配学科名称。

继续使用键 `focubili_learning_list_v2`，内容升级为单一快照：

```json
{
  "schemaVersion": 3,
  "entries": [{ "bvid": "BVfixture", "partCid": 1, "folderId": "stable-folder-id" }],
  "folders": [{ "id": "stable-folder-id", "name": "数学" }]
}
```

上面省略了原条目的其余必需字段；`folderId` 可省略，表示未分组。分组与条目同一次写入，删除组不会出现只写一半的状态。

- 原 v2 数组和 v1 数组均可迁移；BV/CID、进度、状态、排序与日期字段保留。视频身份只要求非空，不强制 BV 前缀，因此课程模块的合成身份可保留；未知合法 JSON 条目字段经 `extraFields` 透传，不在迁移、移动或进度更新时丢弃。
- 迁移前保留原值到 `${originalKey}_migration_backup`，该迁移备份不被后续日常写入覆盖；原有 `${originalKey}_backup` 仍作为最近一次写入备份。
- v1 只在新快照写入并重读验证成功后删除原键；写入拒绝时保留原值与备份。
- 不存在的分组引用回到未分组，不丢任务。未知 schema 或整份损坏值会标记读取失败并拒绝修改，不以空清单覆盖。
- 集成导出应保留该键的完整快照，不能再假设它总是数组。此分支不触碰统一导出实现。

## 风险与边界

- 连续专注现在计入前台浏览、停视频思考和视频切换时间，这是本次规则变更。需要停止累计时应点专注暂停；后台是否触发预期生命周期状态仍需各平台设备确认。
- 异常杀进程可能丢失最后约 15 秒检查点之后的时间，外加存储 I/O 延迟；恢复时保守暂停，不补计离线时间。
- v3 快照写在原 v2 键内。旧版应用不能显示新版快照；降级前需使用备份恢复旧结构。正常升级路径已覆盖，不声称支持透明降级。

状态：实现；故障与专注相关回归自动化通过（31 项）；修复后全量自动化通过（846 通过、1 跳过）；真机未做。此修复追加在首个功能提交 `11120ea` 之后，必须一起整合。

存储继续使用原有 `focubili_focus_active_session` 和 `focubili_focus_history`，没有新增导出键，也没有更改这两个键的 JSON 结构。

- 重启读取时，同 ID 的合法终态历史优先于旧活动快照；不会再删除真正完成的历史并重新计时。统计计算也使用同一优先级。
- 结束归档先写历史并检查返回值、reload 后重读验证，再清理活动键。历史写入拒绝时不会先清活动记录；活动清理拒绝时，已提交的终态仍可阻止重启复活。
- 检查点和重新打开会话先确认活动键写入，再修改历史；活动写失败时不继续覆盖历史。若上轮结束未落盘、下一轮即将覆盖它的唯一活动快照，先补存上轮终态，历史写入仍失败时不覆盖旧活动。重新打开后的历史更新失败时，原终态仍为有效持久状态。
- 删除/清空历史若会移除同 ID 旧活动键的终态保护记录，先成功清理旧活动键，再删终态。清理失败就保留终态，避免删除历史后复活旧会话。
- 所有 `setString` / `remove` 返回值与重读结果都检查。失败后的缓存 reload 仍在同一写入队列内完成，覆盖 SharedPreferences 先改内存缓存后返回 false 的情况。
- `saveState` 返回是否完整保存；存储失败转换为 false，不把异常泄漏给控制器的 `unawaited(_persist())`。自动完成不会因此卡住完成锁。

内存/磁盘边界：控制器仍保留本次内存操作结果，返回 false 不代表这次新状态已经全部落盘。如果归档历史本身被存储拒绝，磁盘保留上一次活动快照，重启只恢复它并安全暂停；无法承诺在设备拒绝写入时仍保存本次新完成结果。如果历史已成功提交、仅活动清理失败，则重启保留完成记录且不重新计时。删除失败时也保留此前终态，需在存储恢复后重试。这是可恢复的双键顺序，不声称具备跨键原子事务。

新增 `test/focus_session_storage_failure_test.dart`，只操作内存夹具：10 项覆盖历史写 false、活动写 false、活动删 false、先变化的本进程缓存、完成/提前结束旧键冲突、终态删除失败、重新打开失败与重试，自动完成写入异常后的下一轮完成，以及上轮归档失败后再次开始的记录保留。
