## 原生审查边界

独立只读审查未发现 Windows/Linux/macOS 新计时器的确定编译或取消缺陷。本机 Windows 探针随后实测通过。

iOS仍需验证：生产 worker 的 `package:` libraryURI、SQLite插件初始化/迁移、重叠前后台工作与销毁；现有独立探针只验证引擎初始化顺序和 ready/complete 握手。系统机会、已有待处理请求的真实取消、真实通知及一小时最小化场景未验证。

`SubscriptionScheduler.swift` 的过期回调未绑定任务身份，存在抽象上的旧回调终止新任务风险；正常一小时调度和25秒watchdog下尚未证实可触发。建议 Apple 审查核对任务身份守卫，不能将其写成已复现缺陷。

## 接续CI与发布门槛

1. 恢复分支先提到 `dev` 的草稿PR，执行 `ci.yml`、`apple-build.yml`、`linux-build.yml`，审查与发现处理完毕后再推进。
2. `release-build.yml` 当前仅 master push/手动触发；PR分支需单独安排精确提交构建。它负责既有签名的Android正式包和Windows安装器，本机未读取签名资料。
3. 最终master精确提交必须有四项成功：CI、Release Build、Apple、Linux。`publish-release.yml` 有发布提交消息门禁；本恢复任务没有触发它。
4. 签名/包名/构建号、下载与覆盖安装验证后，才可执行issue通知、README更新和安全分支清理。#50/#56/#58/#60/#61仍涉及1.9范围，不能因部分1.8实现关闭。

远端只读快照未见今晚旧任务新发布动作；保留 dev/master SHA、最近PR、Actions、标签与Release记录。当前恢复树仅有上述5个常规工作流，GitHub仍显示6个旧版本一次性工作流记录；它们只列为后续审计候选，未禁用、删除或触发。分支清理也未执行，须先确认已合并且没有独有改动、无人依赖。

等待父线程指定唯一发布者。本任务没有push、创建PR、合并、标签、Release、issue写入或远端清理。
