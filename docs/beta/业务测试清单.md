# 焦点哔哩 1.8.0-beta.1 安卓业务测试清单

本轮目的是验证学习任务与本地订阅业务是否适合实际使用。版本：1.8.0-beta.1，pubspec build 21；最低 Android 7.0（API 24）。

## 安装与数据

- 包名 `com.focubili.app.preview`，桌面名称“焦点哔哩 Beta”。与正式版 `com.focubili.app` 共存，数据各自隔离；不会自动复制正式版清单、登录、笔记或缓存。
- 交付的 GitHub CI artifact 是 ZIP，解压后安装其中 app-debug.apk（通用多架构，无需选 ABI）。本地另构建了三种 ABI 用于验证。APK 为 debug 测试构建，启动速度和体积不代表正式 release。
- 同包名且同签名、版本号可升级时，直接覆盖安装通常保留已有 preview 数据。本地模拟器同签名覆盖检查保留了订阅设置与全部已有偏好项；另用明确标注的本地 UI 夹具验证三项学习任务和 93 秒进度跨覆盖安装保持不变。夹具不代表真实视频播放。CI debug 签名与本地/其他历史 preview 可能不同，且 split APK 的 versionCode 高于通用 APK；签名或降级冲突时 Android 会拒绝覆盖。先保留旧应用及数据，不要为安装本测试版直接卸载或清除数据。
- 正式版仍可正常使用。此版本没有新增完整数据导出/恢复功能。重要学习进度、清单和笔记请先自行留存；系统是否能备份应用取决于设备设置，不能当作已验证恢复方案。
- 学习数据沿用 v2 存储。v1 迁移先留备份，成功写入并重读验证 v2 后才移除原 v1。重复加入同一 BV+CID 保持原进度、状态、加入时间与手动顺序。

## 建议先测这条完整流程

1. 打开首页 → 搜索一个多 P 教学视频 → 加入学习清单。选择两节，核对“新增/已存在/剩余容量”，确认后查看清单。
2. 播放其中一节到中间，退出播放器，再从清单继续。应恢复同一 CID 与进度；重新导入同一节不能重置进度。
3. 在 UP 主的 UGC 合集页使用“批量加入学习清单”，选择视频，再选择每支视频的 P。取消应不产生新任务；确认后按选择顺序追加。
4. 我的 → 订阅更新 → 开启。添加 UP 主 mid/空间链接，或 UGC 合集链接/owner mid+seasonId，先核对预览名称再保存。
5. 初次订阅完成扫描后应只显示“基线已建立”，不把所有旧视频当新更新。之后回到前台或手动刷新；出现真实新条目时可播放、标已读、选择 P 加入学习清单。
6. 学习任务与订阅已读互不影响。暂停/删除源后，原学习任务保留。关闭订阅后前台刷新也不再发起源请求。

可用于核对 UGC 参数的公开样例：owner mid `517327498`，seasonId `3993361`。样例存在与内容会变化；遇到风控请保留错误信息并稍后重试。

## 学习清单详细边界

| 场景 | 操作 | 预期 |
|---|---|---|
| 单 P / 多 P | 当前 P、全选、取消若干 P，再确认 | 只有最终选中的 BV+CID 加入；面板显示准确数量 |
| 重复加入 | 给任务留下进度和状态后重复选同一 P | 原任务不重置，不重复，不改变手动排序 |
| 取消 | 面板勾选后返回/点取消 | 清单完全不变 |
| 容量 98+5 | 已有 98 项时选择 5 个新 P | 拒绝整批，不裁掉旧任务；取消或减少至 2 个后可加入 |
| 合集分页 | 进入多页合集，继续加载并选择后页视频 | 只有明确选择的已加载视频加入；不把第一页当整个合集 |
| 详情部分失败 | 批量选择中部分视频失效/网络失败 | 显示失败数量，明确确认后才继续添加成功内容 |
| 状态与排序 | 筛选待学/学习中/已完成；批量改状态/移除 | 已完成置底；搜索、筛选或多选管理时不允许拖动排序 |
| 继续学习 | 从中间任务完成后继续下一任务 | 按手动顺序找后续未完成任务，到末尾不循环 |
| CID 失效 | 原 P 被删除/替换后打开旧任务 | 提示重新选 P，旧任务进度保留，不套用到其他 P |
| 专注关联 | 计时任务关联 P1，播放器切至 P2 | 显示暂停原因，可手动重新关联；批量加入不创建计时任务 |
| 保存失败 | 存储异常时执行加入/改状态 | 不显示成功；保留原数据，可重试 |

## 订阅更新详细边界

| 场景 | 操作 | 预期 |
|---|---|---|
| 默认关闭 | 新安装后进入订阅页 | 功能与通知均关闭，不请求通知权限 |
| 主动订阅 | 输入 mid 或 UGC 链接，预览后保存 | 显示真实名称；普通 series 不作为 UGC 支持 |
| 首次基线 | 新订阅历史很多的源 | 完整扫描后建立基线，未读不因历史增长 |
| UP 新稿 | 基线后 UP 投稿新稿 | 最新页至已知边界及重叠页；新 BV 一次入流 |
| 合集新加旧视频 | 把旧发布日期视频新加进合集后刷新 | 完整分页发现并标“合集新增”；不依赖第一页或发布日期顺序 |
| 同 BV 跨源 | 同支新视频同时来自 UP 与合集 | 一张卡，合并来源名称，不重复系统提醒 |
| 已读独立 | 标已读；播放；加入学习清单分别操作 | 播放/加入不自动标已读；已读不改变学习进度 |
| 今日筛选 | 切换“今日发布” | 以发布时间筛选，发现时间单独展示；未知发布时间不算今日 |
| 暂停/删除 | 刷新中暂停或删源 | 过期异步结果不写入；历史、学习任务不删，不改变 B站关注/收藏 |
| 网络/风控 | 断网、429、风控、会话失效或中途分页失败 | 保留缓存和扫描进度，不推进成功时间；各源独立退避，显示错误与重试时间 |
| 刷新合并 | 连点刷新、切前后台 | 同轮复用锁，默认成功后一小时自动跳过，后台停止周期刷新 |
| 关闭功能 | 请求中关闭再等待响应 | 结果不落地，之后不发新源请求 |
| 缓存与去重 | 历史超过 500 卡片 | 展示最多 500，持久去重索引独立，不因旧卡片淘汰重复提醒 |
| 通知拒绝 | 明确开通知，在 Android 13+ 拒绝权限 | 列表仍可用，通知保持关闭 |
| 通知授权 | 明确开通知并授权，下一轮有真实新内容 | 一轮一条摘要，点击进订阅列表；专注期间只变角标 |

20 个源、两个并发源、每小时自动刷新、每轮每源最多 20 页是 beta 的请求保护值，并非 B站公开接口上限。大源未完成时保存扫描进度，下次手动继续。删除后重新订阅会重新建基线。

## 验证范围和限制

自动化用可控接口模拟覆盖容量、迁移写入拒绝、并发进度、跨源去重、合集分页/乱序、旧视频新增、部分失败、取消后结果、恢复时补跑、首次基线合并、后台初始化、未响应接口超时、详情读取取消、已读与通知拒绝等。它们不能证明真实 B站账号、设备权限及媒体播放成功。

Android 10 软件模拟器实际打开首页、学习清单和订阅页，并检查入口、角标与状态显示。标有“本地 UI 测试夹具”的截图用可控本地数据展示页面，不是实网发现的新稿，也未证明真机播放、账号或通知通过。

真实 HTTP 验证已确认 UGC 合集两页 20+2 条、共 22 条，并观察到发布时间顺序混杂。匿名 UP WBI 请求返回业务风控 -352，旧接口返回 HTTP 412；没有宣称 UP 实网刷新成功。实时接口可能受网络、登录状态与 B站策略影响。

本版本只做启动、前台恢复、手动和前台周期刷新。退出应用后的后台推送、云端推送、常驻服务均未实现。Android 真机播放/账号登录、Android 13+ 权限授权/拒绝与通知点击、OEM 省电行为仍需你验证。
